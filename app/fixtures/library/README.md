# 实验笔记库（fixtures/library）

**这份库是拿来跑实验的**：验收、复现、演示、截图、临时脚本——都在它的**副本**上做。规则见 `docs/06` §7.0「真实库不得用于实验与验收」：用户的真实数据目录**一次也不许动**。

- `project-b.sqlite3` —— 库本体（真相源）。用应用打开某一份**副本**即可。
- `contents.md` —— 只读内容快照（脚本从 SQLite 生成），方便在 Git 里看「这一版比上一版多了什么」。

和 `fixtures/golden_data/` 的分工：那份是**给自动化判据**用的 JSON 数据集（检索/建议/问答的指标），这份是**给人和功能**用的整库（界面、双链、回收站、导入导出、图片附件等，将来都在这上面验）。

## 怎么用

```powershell
# 1) 拷一份副本到临时目录（永远不要在仓库里开库）
$work = "$env:TEMP\moqi-fixture-run"
Remove-Item -Recurse -Force $work -ErrorAction SilentlyContinue
New-Item -ItemType Directory $work | Out-Null
Copy-Item app\fixtures\library\project-b.sqlite3 $work\

# 2) 用这份副本开实例（WebView 用户目录也给它一个独立的）
$env:MOQI_DATA_DIR = $work
$env:WEBVIEW2_USER_DATA_FOLDER = "$env:TEMP\moqi-fixture-webview"
```

**要跑两个实例（同步 / 双端）之前**，先把副本里的身份删掉，否则两份副本是**同一个设备**：

```sql
DELETE FROM app_metadata WHERE key = 'device_id';   -- 应用会自己重新生成
```

## 怎么往里加内容

库本体是真相源，加东西**用应用加**（这样索引、反向引用都由应用自己维护）：

1. 按上面「怎么用」拷贝副本并用应用打开；
2. 照常写笔记（新页面 / 新块 / 新引用都行），确认索引状态里的「拼音覆盖」到齐；
3. **关掉应用**（等它落盘）；
4. 把副本拷回 `app/fixtures/library/project-b.sqlite3`；
5. 重新生成快照（生成脚本在会话临时目录里，逻辑很简单：读 `blocks` 表按父子拼 Markdown），并提交。

**媒体样本那一批是怎么加的（2026-10-07，与上面同一条写入通路）**：图片块要过**原生文件选择框**，脚本驱动不了界面，所以那批是走应用自己用的那条写入命令（`SqliteBlockStore::save_block_json`）写进**副本**的——一次性 Rust 用例，跑完即删；资产文件直接放进 `assets/`。写完用前端的 `parseBlock` / `validateBlockGraph`（应用真正读它的那条路）把 82 行过了一遍：**0 问题**。注意两点：新加的行**拼音列为空**，首次用应用打开时由启动回填补齐（`13` 的检索通路）；**手写 JSON 时 `blockRefs` 与目标块的 `blockBackRefs` 必须成对**，否则校验码里会多出反链不一致。

## 已知缺口（别照着它下结论）

- 「测试笔记」现有 **2 条**反链（不是设计文档里曾提的 5 条）——够测「已引用本篇」，但不够测「反链很多」的观感。
- **没有 mark（高亮）**：行内高亮没落领域层（台账 `D-011`，真缺陷待修）。等高亮进了领域层再补进来——那正好能用这份库验。
- **公式 / 图表 / 白板 / 录音还没有**：这四类块仍未实现，这里是空的。将来实现时，第一个该验的就是「导入导出不丢」。
- 里面的 AI 块是**静态摆件**（`aiMeta` 直接写进去的），不是真模型生成的；要验真实输出，配置真实服务后现场生成。
